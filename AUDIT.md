# Zentro full audit — 2026-11-18

How this was done: five parallel read-only code audits (one per module group) and the gates. Every finding cites code;
"suspected" means reasoned but not reproduced. The only hands-on Chrome testing so far is sign-in as `priya@acme.test`
(owner); a per-module Chrome pass is part of the fix loop and results will be added here.

## The honest summary

- **There are 14 modules, not 21.** `packages/modules/src/registry.ts` has 14. CLAUDE.md's "21" is stale.
- **MODULES.md is wrong.** It marks all 14 as `hardened` with "Open issues: None". That's false. Examples:
  `mail.spec.ts` doesn't exist; `activity.spec.ts` has no chat steps; no spec has an `@<module>` tag, so
  `pnpm test:e2e --grep @tasks` runs **zero** tests and the "module E2E green" step in the Definition of Done has never
  really been checked.
- **Gates are green:** typecheck passes, lint has warnings only, and 1,972 unit tests pass (1,727 of them API). The
  tests are good at org scoping; they miss permission _enforcement_, because `permission-coverage.test.ts` only checks
  that procedures _declare_ permissions.
- **Tenant isolation is solid.** No auditor found a cross-organization leak. The real problems are **inside an
  organization**: members seeing private projects/docs/tickets, permission bypasses, two auth flaws, and several
  half-built features.
- **The uncommitted diff (≈97 files, from 2026-11-04) contains the two worst bugs** (AI/custodian routers with no
  permissions, email-to-task-comment spoofing) and quietly adds them to test allowlists. That breaks "never weaken a
  test".

## 1. Cross-cutting: auth, security, platform

### CRITICAL

- **C1. AI and custodian routers have no permission checks** (`routers/ai.ts`, `routers/custodian.ts`, uncommitted).
  `ai.semanticSearch` returns tasks, docs and tickets from the whole org, private projects included, to any member; it's
  wired into the app-shell search bubble. `detectDuplicateTickets`, `generateLivingSpec` and `sprintBriefing` leak the
  same way. `custodian.runSweep` lets any member write `workLinks` org-wide with no audit. Both are exempted in
  `permission-coverage.test.ts` / `audit-coverage.test.ts`. `suggestStoryPoints` / `triageTicket` are keyword matching
  with a hard-coded `confidence: 0.85` labelled as AI.

### HIGH (found hands-on)

- **Sign-in leaked the password into the URL and the server log** _(fixed and verified)_. The auth forms had no
  `method`, so a submit before React hydrated did a native GET: `/auth/sign-in?email=…&password=…`. That string landed
  in browser history and in the dev server log in plain text. It was reproduced in Chrome.
  - It only fires before hydration: on a slow connection, or when JS fails to load.
  - Fixed by adding `method="post"` to sign-in (×2), sign-up, forgot and reset forms.
  - The server-rendered HTML now shows `method="post"`, and a real sign-in works.

### HIGH

- **H1. Email-OTP sign-in skips 2FA**, including for the platform console. `/sign-in/email-otp` isn't in `disabledPaths`
  (`packages/auth/src/index.ts:290`), and the 2FA hook only matches `/sign-in/email|username|phone-number`. Platform/2FA
  guards check `user.twoFactorEnabled`, not whether this session passed 2FA. It also lets unknown emails sign up as
  verified.
- **H2. Pre-account takeover.** Sign-up auto-signs-in an unverified account; password reset doesn't revoke sessions
  (`revokeSessionsOnPasswordReset` unset); verify-email doesn't either. An attacker who registers your email first keeps
  a live session after you reset and verify. Unverified accounts can also list pending invites
  (`user.listPendingInvites`).
- **H3. Team lead can escalate.** `team.updateMembers` (`team.ts:496-540`) adds anyone to a team without checking the
  caller holds the team's role assignments, so an org-wide role assigned to a team can be handed out.
- **H4. IP allowlist and suspension apply only to tRPC.** Server-rendered pages (`dashboard-data.ts`,
  `overview-data.ts`, `today-data.ts`, members/invitations pages) read the DB directly and skip both checks.
- **H5. An admin can erase an owner.** `privacy.erase` only protects the _last_ owner, with no rank check and no fresh
  sign-in; it leaves role assignments, overrides and API keys behind, which come back on re-invite.
- **H6 (suspected).** `clientIp` trusts the leftmost `x-forwarded-for`; behind a proxy that appends, the IP allowlist
  can be spoofed.

### MEDIUM

- ~~Maintenance mode doesn't cover `/api/auth/*`, `cron/chat`~~ (fixed 2026-11-18) or server-rendered
  `setActiveOrganization` (harmless: it only changes which org a session reads).
- ~~`/organization/create` has no limit~~ (10 owned per person since 2026-11-18; it also respects maintenance).
- `invitation.resend` has no status, seat or role-hold check, so it can re-arm an expired admin invite.
- Admins can demote other admins.
- API-key callers always count as a "fresh" session.
- Platform export leaks `ticketInbox.token`, `intakeForm.token` and the portal token.
- `authenticatedProcedure` doesn't require a verified email.
- Production CSP allows `'unsafe-inline'` scripts, so it gives no XSS protection.
- The burst rate limiter is in-memory per serverless instance.
- **Missing indexes:** `member(organizationId,userId)` (no unique constraint either, so duplicate memberships are
  possible), `session(userId)`, `invitation(organizationId)` and `(email)`, `account(userId)`.
- `loadPermissionSnapshot` runs `ensureSystemRoles` on every request.
- The members page groups the entire session table on every load.
- `admin.security` misses composite roles like `"owner,admin"`.
- **Background jobs run inside user requests.** `runChatJobsLazily` runs scheduled sends, meeting reminders, recurring
  tasks and webhooks from the chat sidebar query; the only other trigger is a daily cron. Quiet orgs never get
  reminders. `getTasksByOrgId` also runs the recurring sweep for _all_ orgs.

### UI

- Sign-in shows the raw "Invalid origin" error plus a second generic "Something went wrong" toast.
- ~~The members list caps silently at 100.~~ Worse: orgs could not pass 100 members at all. Fixed 2026-11-18.
- A failed role change isn't reverted.
- Wrong "If you leave…" banner copy.
- AI endpoints throw plain `Error`, so missing items return 500 instead of 404.

### Missing hardening

SSO/SAML, SCIM, a real error tracker (only a Slack webhook today), per-account lockout after failed passwords, a fresh
sign-in requirement for `eraseMine`.

### Test gaps

- `permission-coverage.test.ts` checks declarations, not enforcement; its `metaOnly` list is dead code.
- No denial tests for AI/custodian.
- No tests for: email-OTP, sign-up then reset with a live session, team-lead escalation, admin erasing an owner,
  suspension/IP on server-rendered pages.
- No platform E2E.

## 2. Projects

### HIGH

- Deleting a private project sets `docs.projectId = null`, which makes its docs **visible to everyone**
  (`project.ts:907`, `access.ts:143`).
- `updateAccess` changes the project's team but not its tasks' and docs' team. The old team keeps permissions and the
  new team gets none.
- The general settings form changes `teamId` with only `projects.update`, skips the "team visibility needs a team"
  check, and silently clears the team if `teamId` is omitted.
- A blocking-link cycle (A blocks B blocks A is allowed) makes `getLongestChain` overflow the stack, so the dependency
  graph 500s for the whole project.

### MEDIUM

- Archived projects stay fully editable.
- Goal key-result values can't be updated or removed from the UI (`goals.updateValue`/`removeKeyResult` have no caller).
- Goals progress counts deleted tasks.
- No pagination; ~~the graph sorts keys as text (P-10 before P-2)~~ (fixed 2026-11-18).

### LOW

- `ownerMemberId` isn't validated against the org.
- Changing a role adds the new one before removing the old, so a failure leaves both.
- `projects.deletedAt` / `tasks.archivedAt` are never written but are filtered on.
- A favorite on something you lost access to can't be removed.

## 3. Tasks

### HIGH

- **Spoofed `teamId` bypasses team roles and deny overrides.** `projectFromInput` trusts the input `teamId`
  (`resources.ts:111`, `engine.ts:88`). This gates createTask, import, templates, recurrence, sprints and automations.
- **`customField.valuesForTask` leaks private-project data** to any member (no resource check).
- **Automations:** any member can create an org-wide rule that runs on private-project tasks and posts their keys to a
  channel; `toggle`/`delete` have no resource check; there's no module gate and no audit.
- **Two automation triggers never fire** (`task.created`, `task.blockers_resolved`), including the seeded preset
  "Auto-start task when blockers clear".
- **View-only users can log time** via `timesheet.start/stop`. `timesheet.report` lists private and deleted task names.

### MEDIUM

- ~~Templates over 100 points always fail, and subtasks are created one call at a time (partial on failure).~~ Fixed
  2026-11-18.
- Tasks created or imported as done get no `completedAt`, so burndown misses them.
- `updateTaskByKey` accepts `timeSpentMinutes` directly, which desyncs it from time logs.
- ~~Deleting a task orphans its subtasks, and there's no restore.~~ Subtasks are kept as tasks, and deleted tasks can be
  restored from `/tasks/trash` (2026-11-18).
- `getTasksByOrgId` loads the whole org with no limit and runs the recurring sweep in the request.
- Bulk edit sends one request per task, and the toast says "reassigned" for any change.
- All dates are UTC: recurrences at 09:00 UTC, timesheet days, "today".
- Any member can pause or delete anyone's recurring rules.

### Missing vs Linear/Asana

Edit/delete comments, edit/delete time logs, rename/reorder custom fields and edit options, update saved views, filter
by custom field, a bulk endpoint, trash with restore.

  private projects. `search.searchById` returns private channels/DMs by id. Both are exempted in the coverage test.
- **Restoring a version immediately conflicts:** `doc.updatedAt` goes stale, so the next autosave always gets CONFLICT.
- ~~**Version history never captures the latest state:** only the first save per 10-minute window is snapshotted.~~
  Fixed 2026-11-18 (`docVersion`).

### MEDIUM

- `restoreVersion` accepts arbitrary client content with no conflict check.
- `expectedUpdatedAt` is optional.
- A title save can race a content save.
- Version procedures lack `module: "docs"` and ignore `deletedAt`.

### LOW

- Search `ilike` doesn't escape `%`/`_`.
- Duplicate slug → 500.
- Comment payloads include author emails.
- Link-insert race.
- `//host` links allowed.

### Missing

Real sharing (Share only copies the URL), comment edit/delete/resolve/threads, trash purge, co-editing, images/embeds,
export, nested pages.

  allowing only your own uploads and chat attachments. With Chat off, Files downloads break completely.
- **The library leaks private chat/DM attachments** (names and uploaders) to anyone with `files.view`;
  `files.delete_any` can delete them.
- **Deleting from the library breaks chat messages that use the file**, despite a comment saying otherwise.

### MEDIUM

- `files.get` reveals private channel names via `sharedIn`/`usedIn`.
- ~~Deleted bytes are never removed~~ (purged after 30 days since 2026-11-18); the quota already excluded deleted rows.

### LOW

- ~~Quota check race.~~ Fixed 2026-11-18 (per-org lock).
- MIME type not verified (low: downloads are allow-listed, `nosniff`, sandboxed).
- Rename is gated on `delete_own`.
- Upload buttons show without `files.upload`.
- Silent cap at 300 files.
- Search response race.
- "Cannot be undone" copy on a soft delete.

**Inbound email posts task comments under a forged sender.** `ticket-inbound.ts:143-183` trusts `from`, with no SPF/DKIM
check, no `tasks.comment` permission and no project-visibility check. It writes into hidden projects, isn't audited,
double-posts on provider retry, and has no test.

### MEDIUM

- Public endpoints (intake, portal, inbound, help centre) ignore suspension and the module toggle.
- Spam tickets reopen on any reply.
- `kb.suggest` can paste _internal_ articles into customer replies.
- Linked task names leak past project visibility.
- An intake flood serializes the org's ticket numbering (no CAPTCHA, no per-form cap).
- The portal hangs on "Loading…" on any error.
- The public intake form shows "can't find that form" for 429/503.

### LOW

- Field renumbering mismatches stale forms.
- KB slug race.
- Replies go out on spam tickets.
- Replies aren't audited.
- AI button shows when AI is off.
- Portal replies are labelled "by email".

### Missing

Submitter acknowledgement email, assignment rules, business-hours SLAs, breach alerts, CSAT, merge, macros.
